# CSCAN/2 结果格式

`.cptr` 是本工具的结果格式，不与其他工具的专有二进制格式直接互通。1.2.0 默认写 CSCAN/2，仍能读取 1.1.0 及更早版本写出的 CSCAN/1。扩展名只是约定，程序会校验文件签名和内容。

CSCAN/2 文件结构如下，所有整数均为小端序，不使用 C++ 结构体填充：

1. 8 字节签名：ASCII `CSCAN02\n`。
2. u32 元数据 JSON 长度，最大 4 MiB。
3. UTF-8 JSON 元数据和 u32 CRC-32/IEEE。元数据至少包含 `format`、`version`、`count`、`count_text`、`complete`、`reason`、`kind`；扫描结果还包含 `representation`、图统计和读取统计。
4. 压缩数据块序列。每块前有 `raw_bytes:u32` 和 `packed_bytes:u32`，随后是一个带校验的 Zstandard 帧；两个长度都为 0 表示结束。单块原文最多 1 MiB，块之间可以独立解压。链记录流按块读取；图结果加载受预算限制的节点结构，分页时仅展开需要的链，不把全部路径物化成文本。

压缩块原文使用无符号变长整数（7 位数据位）和 ZigZag 有符号变长整数。解码器拒绝非规范整数、溢出、截断块、尾部垃圾和 Zstandard 校验失败。

`representation: "chains"` 是紧凑链记录流：

- 每条记录先写根上下文标志；根改变时写一次根类型、位数、掩码、模块编号、模块名和区域名。
- 随后写偏移数量和 ZigZag 偏移序列。根偏移必须非负，解引用偏移可为负。
- 模块上下文复用和变长偏移主要服务导入文本、旧结果转换和混合输入；比较时仍按完整链语义去重。

`representation: "graph"` 是扫描、关系搜索、图比较和图过滤的默认表示：

- 先写节点数量；节点按创建顺序排列，边只能指向更早的节点，因此不会形成回环。
- 每个节点写终点标志、边数量，以及按偏移排序的 `(offset, child_node)`。终点节点代表一条完整链的末端；共享后缀只保存一次。
- 再写根数量和根键。根键包含模块/@start 类型、位数、掩码、模块编号、模块名和区域；根节点的第一层偏移必须非负。
- 读取器按路径计数校验文件头 `count`，分页预览和文本导出采用流式图展开。图内存预算由 `graph_memory_mb` 控制，超限不会把未验证的结果标记为完整。

扫描、关系、比较和在线过滤产生图结果；混合 CSCAN/1、CSCAN/2 链流或导入文本时，比较会退回有界外部排序。图比较直接在共享节点上求交集，避免先把每条链全部展开。图结果可以继续比较、过滤、分页和格式化。

格式化文本是显式转换，不是把后缀改成 `.txt`：

```text
cscan format --data ./data --file common.cptr --output common.txt
```

输出为 UTF-8 文本，带 `# CSCAN-TXT 1` 头和完整状态；`format` 按深度和数量限制流式写入，完成后才通过同目录 rename 发布。网页的“格式化文本”按钮执行同一转换并下载生成的文件；“快速导出文本”则直接把二进制结果流式展开到浏览器。

CSCAN/1 仅用于兼容读取。它的结构是 `CSCAN01\n`、元数据、逐条 u32 长度/记录体/u32 CRC；记录体保存根类型、位数、掩码、模块身份和固定 8 字节 i64 偏移。新版本不会覆盖或原地升级旧文件，比较时会按读取器选择图路径或旧的外部排序路径。

文本链示例：

```text
# CSCAN-TXT 1 {"bits":64,"mask":"none","complete":true}
libexample.so[1][Cd] + 0x40 -> + 0x20 -> - 0x30
@start + 0x18 -> + 0x0
```

输入文本严格校验，单行最多 16 KiB；网页粘贴文本最大 8 MiB，文件选择使用 1 MiB 分块上传（文件最大 64 GiB），CLI 文件导入逐行读取。区域简称和链语义见 `README.md`。结果文件不接受覆盖，临时文件、头部校验和数量校验用于避免把截断文件列入结果库。

## 1.2.1 过滤输出选择

`filter --output-format binary` 保存 CSCAN/2（默认）；`filter --output-format text --output matched.txt` 在同一任务中直接生成文本。文本带 `kind: filter`、原始输入名、链数及完整状态，结果上限造成的不完整状态会保留。输入和同名输出不可覆盖。生成的文本可以出现在文件列表中继续预览、对比和过滤。无头文本预览默认按 64 位解释；加载过滤时应选择目标实际位数。
