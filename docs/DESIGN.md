# 设计说明

产品名：C扫指针工具第一版（1.2.2）。界面为内置网页，扫描逻辑为 C++17；网页不依赖 npm、CDN、云服务或额外 Python 服务。第三方头文件已随源码保存。作者：jx小新。

## 界面

采用中文工作台，深绿色侧栏、浅色内容区、绿色主操作。桌面主配置与任务状态并列；手机使用五项底部导航、单列配置。地址、指针和偏移使用等宽字体。状态同时提供文字和颜色；保留焦点环、原生可键盘关闭的对话框和 reduced-motion 支持。搜索阶段没有可靠总量时不显示虚假的百分比。

采用系统字体，支持离线运行。

## 核心职责

- `memory.cpp`：严格配置解析与真实自测内存。
- `process.cpp`：进程可见性、真实内核身份、maps/模块与 PID 绑定。
- `readers.cpp`：普通读取与 Paradise 适配、精确读取、通道诊断。
- `scan.cpp`：有效字节采集、并行索引、反向查链、正向地址关系、统一链解析。
- `graph.cpp` / `graph_scan.cpp`：共享后缀图、图交集、当前进程图过滤、图路径流式展开。
- `store.cpp`：CSCAN/2、独立 Zstandard 块、链/图表示、CSCAN/1 兼容读取、原子发布与禁止覆盖。
- `text.cpp`：文本链流式读取和显式格式化转换。
- `operations.cpp`：扫描/比较/仅计数/过滤/调试/导入任务。
- `server.cpp`：本机 HTTP、会话令牌、单任务调度、状态及取消、流式下载。
- `main.cpp`：CLI 与中文终端菜单。
- `web/`：响应式 HTML/CSS/JavaScript；构建时嵌入 ELF。

## 第一版算法与语义

采集保存 `(address,value)`；普通 syscall/pread 默认把内存区间拆成块并行读取，Paradise 保持串行调用。读取实际成功的字节，短读继续处理，失败按运行时页边界跳过。保留最多 `pointer_width-1` 字节连续尾部，支持 8 字节指针在 4 字节步进和分块边缘的采集。判断值必须落入有效映射的 `[start,end)`。

反向索引按 `(value,address)` 排序。每层以二分查找定位允许值区间，再把相同后缀合并到共享图节点；到达选定模块根时把根偏移合并，公共路径不会因全局 visited 被丢弃。有限深度内允许重复地址路径，所以环形引用可能消耗搜索预算。图节点记录路径数量、长度和溢出状态，结果上限、图内存、时间与工作量预算控制指数增长，并明确标记截断。

普通扫描深度表示解引用次数；深度 0 可输出目标所在模块的直接偏移。层号从目标端向根计算。偏移上限默认十进制，也接受 0x；地址始终十六进制。根偏移以实际映射段起点为基准，不冒充统一 ELF 加载基址。根身份为模块名、同名同区域映射编号及区域；编号由地址顺序生成。跨版本或映射拆分变化后需要重新验证。

关系扫描起点是 `@start`。首次采集的指针地址位于 `[start,start+offset)`，后续每层及末级均允许 `[0,offset]` 的正偏移；一条链可有多个不同父路径。调试/过滤时必须提供本次有效起始地址。

比较按根类型、模块身份、指针宽度、标签策略及完整有符号偏移序列求交集。CSCAN/2 图输入直接按根和共享节点求交集；CSCAN/1、链记录和文本混合时使用约 8 MiB 的排序分块、双路归并和多输入交集。结果可继续输入下一轮，比较时 ASLR 地址不参与键。任何不完整输入会让输出继承不完整状态。

采集是当前进程的非原子快照；解析/过滤也不能冻结目标。界面连接保存 PID 身份，任务执行时核对身份；过程定期核对进程启动时间。成功链意味着本次读取支持该路径，不保证未来永久稳定。

## 读取器

`syscall` 使用标准 process_vm_readv，`pread` 只读打开 /proc/PID/mem。Paradise 3.5 对应本地 ioremap 读取协议，优先使用显式继承 FD，其次匹配已有 FD，再向已存在驱动请求接口；旧 Hook 使用 AF_DECnet socket 与独立 ioctl。均不加载驱动、不中途静默退回普通后端。初始化与读取结果分别判定。

两种 Paradise 协议仍需在真实设备上验证驱动版本和返回契约；成功返回按协议约定表示整段成功，失败整段无效。不包含写内存、隐藏、触摸、传感器、断点或全局 syscall 转接功能。

内核读取与 maps 枚举是独立能力；maps 不可读时明确报错。不要把 proot 中的身份显示当成真实 Android 权限。
